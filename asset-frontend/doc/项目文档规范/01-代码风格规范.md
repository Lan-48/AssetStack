# 代码风格规范

## 命名规范

常量：大写字母+下划线 (UPPER_CASE)
变量：小驼峰 (camelCase)
函数：小驼峰 (camelCase)
类：大驼峰 (PascalCase)
接口：大驼峰 (PascalCase)
类型：大驼峰 (PascalCase)
组件：大驼峰 (PascalCase)
文件名：小写字母+连字符 (kebab-case)

例如：
```typescript
const MAX_LENGTH = 100;
const userInfo = {
  name: 'John',
  age: 20,
};
function getUserInfo() {
  return userInfo;
}
interface UserInfo {
  name: string;
  age: number;
}
```

## 颜色和样式规范

- **统一来源**  
  - 所有颜色、字体大小、阴影、圆角、透明度等视觉样式相关的“常量”，必须从 `src/common` 目录下已有的配置或样式中统一引用，不允许在业务代码/组件中随意定义。  
  - 涉及的主要文件包括但不限于：`theme.ts`、`theme.scss`、`common.scss`、`uni-ui.scss` 等。

- **禁止直接写死样式值**  
  - **禁止自定义颜色**：不得在代码中直接书写诸如 `#123456`、`rgb(...)`、`rgba(...)`、`hsl(...)` 等颜色值，必须使用 `common` 目录中已经定义好的颜色变量或类名。  
  - **禁止自定义透明度**：不得随意写 `opacity: 0.3`、`rgba(..., 0.7)` 等自定义透明度，统一使用 `theme.ts` / `theme.scss` 中预设的透明度变量。  
  - **禁止自定义字体**：不得在业务代码中随意指定 `font-family`，必须使用全局已定义的字体栈；`font-size` 只能使用 `common.scss` 中已定义的字号体系（变量或混合指令/类名），不得随意写如 `13px`、`17px` 等不在体系内的字号。

- **新增样式规范**  
  - 如确有业务需要新增颜色、字号、阴影、圆角等样式，应先在 `common` 目录对应文件中补充统一的变量/混合指令/工具类，经评审通过后，再在业务代码中引用。  
  - 任何绕过 `common` 目录、直接在局部写死视觉样式的实现，视为不符合项目规范。
